## 2. Schema.org JSON-LD Invariants

Schema is generated by [`src/lib/schema-generators.ts`](../src/lib/schema-generators.ts) (682 lines) and assembled in `Head.astro` (lines 98–205). Every schema object must contain `"@context": "https://schema.org"` and a valid `"@type"`. Invalid or null schemas are filtered before emission.

### 2.1 Schema array by `pageType`

| `pageType` prop | Schema types emitted | Conditions |
|---|---|---|
| `home` | `WebPage`, `BreadcrumbList`, `LocalBusiness`, `Person` | `includeBreadcrumbs=true` (default), `includeLocalBusiness=true` |
| `about` | `WebPage`, `BreadcrumbList`, `LocalBusiness`, `Person` | Same |
| `contact` | `WebPage`, `BreadcrumbList`, `LocalBusiness`, `Person` | Same |
| `service` | `WebPage`, `BreadcrumbList`, `LocalBusiness`, `Service` | `serviceData` prop must be provided |
| `article` | `Article`, `BreadcrumbList` | `article=true` prop implies `pageType='article'` |
| `faq` | `WebPage`, `BreadcrumbList`, `FAQPage` | `faqs` prop must be provided |
| `campaign` | `WebPage`, `BreadcrumbList`, `Event` | `campaignData` prop must be provided |
| `default` | `WebPage`, `BreadcrumbList` | Fallback for all other pages |

### 2.2 Fallback chain (must survive upgrade)

```
generatePageSchema(schemaOptions)
  → if throws or returns empty → safeSchemaGeneration(fallbackFn)
    → fallbackFn returns [baseSchema] (Article or WebPage with author/publisher)
      → if that too is empty → hardcoded minimal WebPage schema
```

The minimal WebPage fallback (Head.astro lines 190–197):
```json
{
  "@context": "https://schema.org",
  "@type": "WebPage",
  "url": "<site.url><path>",
  "name": "<title>",
  "description": "<description>",
  "inLanguage": "<site.siteLanguage>"
}
```

This fallback must always render as a last resort. Any upgrade that causes unhandled exceptions in schema generation silently degrades rich snippet eligibility.

### 2.3 Schema validation rules enforced before emission

- `schema !== null && typeof schema === 'object'`
- `schema['@context']` is present and truthy
- `schema['@type']` is present and truthy

If a schema fails these checks it is filtered and a console warning is emitted — but the page does not error.

## 6. Analytics Consent and Opt-Out Contract

The following functions are defined inside a `<script is:inline>` block in [`src/components/Head.astro`](../src/components/Head.astro) (lines 441–578) and assigned to `window` (lines 574–579). They must remain callable by any component after the `<ClientRouter />` swap.

### 6.1 Global function signatures

```javascript
// Check if the user has given analytics consent (via cookie)
window.checkAnalyticsConsent(): boolean

// Check if the user has explicitly opted out (via opt-out cookie)
window.hasOptedOut(): boolean

// Set analytics consent (writes `analytics_consent` cookie, 1-year expiry)
// Also calls window.gtag('consent', 'update', ...) if consenting
window.setAnalyticsConsent(consent: boolean): void

// Set opt-out preference (writes opt-out cookie, 1-year expiry)
// Calls window.gtag('consent', 'update', {'analytics_storage': 'denied'}) if opting out
window.setOptOutPreference(optOut: boolean): void

// Track an engagement event with GA4 + Clarity (respects consent/opt-out)
// Calls window.gtag('event', eventName, {...parameters, event_category: 'engagement'})
// Calls window.clarity('event', eventName, parameters)
window.trackEngagementEvent(eventName: string, parameters: object): void

// Track a conversion event with GA4 + Clarity (respects consent/opt-out)
// Calls window.gtag('event', eventName, {...parameters, event_category: 'conversion'})
// Calls window.clarity('event', eventName, parameters)
window.trackConversionEvent(eventName: string, parameters: object): void
```

### 6.2 Cookie names (must not change)

| Cookie | Name | Expiry | Set by |
|---|---|---|---|
| Consent status | `analytics_consent` | 1 year | `setAnalyticsConsent()` |
| Opt-out preference | `optOutCookieName` (resolved from `analyticsConfig.optOutCookieName`) | 1 year | `setOptOutPreference()` |

The opt-out cookie name comes from `src/config/site.js` → `analytics.privacy.consentStorageKey` = `'meteoric_analytics_consent'`.

### 6.3 Consent gate logic

All tracking functions check: `if (hasOptedOut() || (requireConsent && !checkAnalyticsConsent())) return;`

`requireConsent` is derived from `analyticsConfig.consentRequired` (= `site.analytics.privacy.cookieConsentRequired`). When `true`, no event fires without the consent cookie.

### 6.4 Global dependency chain

Components that call `window.trackEngagementEvent` or `window.trackConversionEvent` must execute **after** `Head.astro`'s inline script has run. Since `Head.astro` is rendered in the `<head>`, and the inline script has no `defer`, this order is guaranteed on initial page load. After `<ClientRouter />` navigations, the `<head>` is not re-rendered — the globals persist on `window` and remain callable.

**Risk**: if a component calls these globals before `Head.astro` has rendered (e.g., in an island with `client:load`), the call would throw `TypeError: window.trackConversionEvent is not a function`. Current components avoid this by calling from `astro:after-swap` or `DOMContentLoaded` listeners that fire after the head script.

## 7. `astro:after-swap` Re-attachment Contract

When `<ClientRouter />` is enabled (currently `<ViewTransitions />`), Astro fires `astro:after-swap` after each client-side navigation. The `<head>` is **not** re-rendered; only the `<body>` changes. All eight listener registrations listed below must survive the `<ClientRouter />` rename (Phase 3).

### 7.1 Complete listener inventory

| File | Listener registration (line) | What it re-attaches | Why re-attachment is needed |
|---|---|---|---|
| [`src/components/Head.astro`](../src/components/Head.astro) | Line 607 | `tel:` and `mailto:` click tracking via `trackConversionEvent` | DOM is replaced; new links need listeners |
| [`src/components/Head.astro`](../src/components/Head.astro) | Line 679 | `addCopyCodeButtons()` | Code blocks in new page body need copy buttons |
| [`src/components/CampaignCTA.astro`](../src/components/CampaignCTA.astro) | Line 541 | `initCampaignCTA()` — campaign CTA interaction listeners | Component body re-rendered after navigation |
| [`src/components/CampaignHero.astro`](../src/components/CampaignHero.astro) | Line 218 | `initCountdownTimer()` — countdown timer restart | Timer must restart on new page body |
| [`src/lib/utm-tracking.ts`](../src/lib/utm-tracking.ts) | Line 344 | `UTMTracker.initialize()` — re-reads UTM params from new URL | Navigation URL may have different UTM params |
| [`src/lib/resource-form.js`](../src/lib/resource-form.js) | Line 348 | `initializeResourceForms()` — resource download form listeners | Form elements re-rendered; listeners lost |
| [`src/pages/offers/[...slug].astro`](../src/pages/offers/%5B...slug%5D.astro) | Line 580 | `initCampaignAnalytics()` — offer page analytics tracking | Page-specific conversion tracking |
| [`src/pages/offers/expired.astro`](../src/pages/offers/expired.astro) | Line 209 | `trackExpiredCampaignVisit()` — expired offer tracking | Fires campaign visit to `/api/campaign-visit` |

**Total**: 8 listener registrations across 7 files (Head.astro has 2).

### 7.2 What must be true after Phase 3

1. `astro:after-swap` fires on every `<ClientRouter />` navigation (verify in DevTools console).
2. Each function called in the listeners still exists in scope when the event fires.
3. `window.trackConversionEvent` and `window.trackEngagementEvent` remain defined (they are set once in Head.astro's head script and persist on `window`).
4. UTM parameters are re-captured from the new URL after navigation.
5. Copy-code buttons appear on code blocks in articles navigated to via client-side routing.
6. Campaign countdown timers restart correctly on offers pages.

### 7.3 What changes between `<ViewTransitions />` and `<ClientRouter />`

The `astro:after-swap` event continues to fire with `<ClientRouter />` — it is not renamed. The rename is import-only:

```astro
<!-- Before (Astro 4/5 alias, removed in Astro 6) -->
import { ViewTransitions } from 'astro:transitions';
<ViewTransitions />

<!-- After (Astro 5+, required in Astro 6) -->
import { ClientRouter } from 'astro:transitions';
<ClientRouter />
```

No changes are needed in any of the 7 consumer files — the event name `astro:after-swap` is stable.

## 8. Diff-Driven Verification Protocol

This is Jules's exact verification procedure. It must be executed before any upgrade phase branch is merged.

### 8.1 Pre-upgrade baseline capture

Run on the current `main` branch (Astro 4.15.12) before any upgrade work begins.

```powershell
# 1. Build the site
npm run build

# 2. Capture RSS and sitemap
Copy-Item dist/rss.xml tests/baseline/rss.xml
Copy-Item dist/sitemap-index.xml tests/baseline/sitemap-index.xml
Copy-Item dist/sitemap-0.xml tests/baseline/sitemap-0.xml

# 3. Capture rendered HTML for one URL per content collection
# Save as: tests/baseline/html/<collection>-detail.html
# Required pages (use any non-draft entry from each collection):
#   articles/  notes/  works/  illustrations/  bibliophilediaries/  saasguide/  faqs/
#   Also capture: home (index.html), about, contact, one service page, one tag page

# 4. Extract just the <head> from each HTML file for focused diffing
# Focus sections: <title>, all <meta>, <link rel="canonical">, all <script type="application/ld+json">
```

### 8.2 Post-phase verification

Run after each phase branch builds green.

```powershell
# 1. Build the upgrade branch
npm run build

# 2. Diff RSS — any item link change is a stop signal
Compare-Object (Get-Content tests/baseline/rss.xml) (Get-Content dist/rss.xml)

# 3. Diff sitemaps — any URL change is a stop signal
Compare-Object (Get-Content tests/baseline/sitemap-index.xml) (Get-Content dist/sitemap-index.xml)
Compare-Object (Get-Content tests/baseline/sitemap-0.xml) (Get-Content dist/sitemap-0.xml)

# 4. For each captured HTML page:
#    - Confirm <title> is identical
#    - Confirm <link rel="canonical" href="..."> value is identical
#    - Confirm og:url value is identical
#    - Confirm all JSON-LD @type values are identical
#    - Note: asset hashes in <script src="..."> and <link href="..."> will change — expected
```

### 8.3 Stop conditions

Any of the following halts the upgrade and requires Claude (Architect) review before continuing:

| Condition | Stop reason |
|---|---|
| RSS `<link>` changes for any existing entry | URL drift = broken RSS links for subscribers |
| Canonical URL changes for any content route | SEO regression — duplicate content risk |
| `og:url` changes for any page | Social sharing links break |
| JSON-LD `@type` array loses a schema type | Rich snippet eligibility loss |
| Sitemap includes `/api/*` routes | API routes should never appear in sitemap |
| Sitemap loses any content route URL | Deindexing risk |
| `astro:after-swap` does not fire after Phase 3 | Analytics and form listeners fail silently |
| Any API route returns 500 on `npm run cfpreview` | D1 connectivity broken |

### 8.4 Phase 3 analytics smoke test

In addition to the HTML diffs, Jules runs this manually on a Cloudflare Pages preview URL after Phase 3:

1. Open browser DevTools → Network + Console tabs.
2. Load home page (`/`). Confirm no JavaScript errors.
3. Click a nav link to navigate to an article. Confirm `astro:after-swap` fires (add `document.addEventListener('astro:after-swap', () => console.log('swap fired'))` in DevTools).
4. On the article page, click a `tel:` link. Confirm `phone_click` event appears in GA4 DebugView (`https://analytics.google.com/analytics/web/#/p<property>/debugview`).
5. Click a `mailto:` link. Confirm `email_click` event in GA4 DebugView.
6. Navigate to a page with a code block. Confirm copy-code button appears.
7. Navigate to `/offers/<any-slug>`. Confirm UTM parameters are captured if present in the URL.
8. Confirm `window.trackEngagementEvent` and `window.trackConversionEvent` are callable from DevTools console without throwing.
